b-speak domain model

The plan from docs/architecture.md, drawn out: where each piece runs, every command, event and policy, how audio streams in and out of the domain, and a worked example of two agents sharing the room with you. v1 is built: the host, CLI, speech engines and headset audio all run, and the domain is covered by tests.

Where it runs

One resident host per machine owns the headset and the models. Every agent talks to it through the bspeak CLI, which is a thin client over the host's local HTTP API. An MCP server later is just another client of the same API.

Audio streams

Capture and playback are a streaming pipeline, a supporting subdomain behind ports. They are not modeled as commands. The pipeline touches the domain at exactly four points: speech onset, a finished transcript, the floor being granted, and the last sample played.

Headset only in v1The mic cannot hear the agent, so there is no echo to cancel and barge-in works with plain voice detection. Room speakers need acoustic echo cancellation later.
Zero frames, never drop themThe endpointer closes a turn by counting trailing silence. Anything that suppresses audio upstream must emit silence, or turns stop ending.
While listening is pausedVoice detection and transcription keep running so the host can hear "start listening". Every other transcript is discarded on the spot and never reaches the event log.
First sentence firstSpeech is split into sentences and playback starts when the first one is synthesized. A jitter buffer with a short pre-roll rides the gaps between sentences.
